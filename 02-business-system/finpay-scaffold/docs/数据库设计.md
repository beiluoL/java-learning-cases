# 数据库设计说明（FinPay）

库名：`finpay`（utf8mb4）。所有金额字段使用 `DECIMAL(18,2)`，下单金额单位为「元」（微信渠道内部换算为「分」）。

## 表清单

| 表名 | 作用 | 关键约束 |
|---|---|---|
| `t_merchant` | 商户 | `merchant_no` 唯一 |
| `t_payment_order` | 支付订单 | `out_trade_no` 索引（幂等键）；`status` 状态索引 |
| `t_refund_order` | 退款订单 | `out_refund_no` 索引（幂等键） |
| `t_account` | 银行账户 | `account_no` 唯一；含 `balance`/`frozen` 支持 TCC |
| `t_bank_transaction` | 银行流水 | `branch_id` 索引（TCC 分支关联） |
| `t_audit_log` | 操作审计 | `action`/`occur_time` 索引 |
| `t_channel_config` | 渠道配置 | `(channel, merchant_no)` 唯一 |
| `t_reconcile_batch` | 对账批次 | `biz_date` 索引 |
| `t_reconcile_detail` | 对账差错明细 | `batch_id` 索引 |

## 核心表结构

### t_payment_order（支付订单）
| 字段 | 类型 | 说明 |
|---|---|---|
| out_trade_no | VARCHAR(64) | 商户订单号，**幂等键** |
| trade_no | VARCHAR(64) | 渠道交易号 |
| channel | VARCHAR(32) | alipay / wechat |
| merchant_no | VARCHAR(64) | 商户号 |
| amount | DECIMAL(18,2) | 金额（元） |
| status | VARCHAR(32) | PayStatus 枚举名 |
| callback_raw | TEXT | 回调原始报文（审计留痕） |

### t_account（银行账户，TCC 支撑）
`balance` 为可用余额，`frozen` 为 TCC Try 阶段冻结金额。
- Try：`balance -= amt, frozen += amt`
- Confirm：`frozen -= amt`（转出方），对方 `balance += amt`
- Cancel：`balance += amt, frozen -= amt`

### t_channel_config（渠道配置）
`config_json` 存放渠道私有参数（应用私钥、支付宝公钥、微信私钥、证书序列号、APIv3Key 等）。**生产环境必须加密存储**（接 KMS），本脚手架以明文示意。

## 索引策略
- 支付/退款以「商户订单号」为高频查询维度，建立单列索引。
- 对账按日期扫描，建立 `biz_date` 索引。
- 审计按操作类型 + 时间检索，建立复合/单列索引。

## 数据加密
- 银行卡号、持卡人等敏感字段经 `SensitiveConverter`（AES）落库加密，读取自动解密。
- 渠道私钥等密钥不在数据库以明文长期留存，由 KMS 注入到运行内存。
