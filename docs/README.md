# docs · 跨工程文档

> **这一组放什么**：不属于任何一个具体工程、但支撑所有工程的方法论资料 —— 系统设计方案、技术选型对比、设计资源清单。
>
> **为什么单独成组**：这些文档的价值在于**可复用**。写一个 IM 系统方案时不想去翻某个具体工程目录；放在 `docs/` 下按主题分目录，任何工程都能引用同一份。

---

## 目录结构

```text
docs/
├── README.md                          # 本文件
├── 技术方案/                          # 7 篇「某类系统怎么实现」的技术方案
├── 系统设计/                          # 系统设计方案库（含索引 README）
│   ├── README.md                      # 方案清单索引（新增方案时同步更新）
│   ├── 短网址系统/
│   ├── 全球视频流系统/
│   └── 打车系统/
└── 移动端UI设计开源Skill清单.md        # 移动端 UI 设计开源 Skill 资料汇总
```

## 约定

- 文档用 Markdown，图优先 Mermaid（便于版本管理与 diff），关键数据用表格。
- 新文档按主题归入 `技术方案/`（面向"怎么做这套系统"）或 `系统设计/`（面向"某系统方案设计"），不要平铺在 `docs/` 根下。
- 文档若要引用具体工程的代码，用**仓库根相对路径**（如 `03-ai-agent/rag-doc-qa-system`），不要用 `../` 翻上级目录。
