# RAG 检索增强生成学习笔记

RAG（Retrieval-Augmented Generation，检索增强生成）把“检索”和“生成”结合起来：先从一个知识库里召回与问题最相关的片段，再把这些片段作为上下文喂给大模型，让它基于证据作答，从而减少幻觉。

## 一、为什么需要 RAG

大模型的知识来自训练语料，存在截止日期，且容易在陌生领域编造答案。RAG 让模型“先查资料再回答”，把答案锚定在可检索的私有文档上，非常适合企业知识库、客服助手等场景。

## 二、典型链路

1. 文档摄取（Ingestion）：用 Apache Tika 等工具把 PDF、Word、HTML 解析成纯文本，并抽取标题、作者等元数据。
2. 分块（Chunking）：长文切成若干 chunk，控制单块长度，便于精准召回。
3. 向量化（Embedding）：每个 chunk 经 Embedding 模型变成向量，写入 Milvus 等向量库。
4. 召回（Retrieval）：用户提问时，把问题也向量化，在向量库里找最近邻的 chunk。
5. 生成（Generation）：把召回的 chunk 拼成上下文，连同问题一起发给大模型生成答案。

## 三、关键权衡

- 分块大小：太大召回不精准，太小丢失上下文。常见 300~800 字、带少量重叠。
- 嵌入模型：语义质量直接决定召回上限。本地教学可用哈希式嵌入，生产建议用 OpenAI、Ollama 或国产大模型。
- 向量库：Milvus 适合海量规模；小规模也可选 PGVector、Chroma 等。
