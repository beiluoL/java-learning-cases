# AI 智能体开发规则

> 文档编号：ENG-AI-001  
> 版本：1.0  
> 生效日期：2026-10-26  
> 适用对象：**任何在本仓库新增或修改代码的智能体**（含人，人亦适用）  
> 强制力：**违反「禁止」条款的改动不得提交；门禁不通过不得提交**  
> 上位文档：[`CODE_STANDARDS.md`](./CODE_STANDARDS.md)  
> 配套：[`CODE_REVIEW_CHECKLIST.md`](./CODE_REVIEW_CHECKLIST.md) · [`QUALITY_GATE.md`](./QUALITY_GATE.md)

## 0. 这份文档解决什么问题

审计结论（`PROJECT_CODE_AUDIT.md`）的第一个根因不是"某个类写得不好"，而是：

> **规范只写在 Markdown 里，靠自觉执行，所以不执行。**

智能体的特殊风险在于：它会**自信地**产出看起来合理的代码，并声称"已完成"。
没有门禁时，没人能区分"真的完成了"和"看起来完成了"。

因此本文档把规范变成**可执行的指令序列**：
先做什么、后做什么、什么绝不允许、做完怎么自证。

## 1. 优先级顺序（冲突时按此裁决）

| 优先级 | 原则 | 说明 |
|---:|---|---|
| 1 | **不改变业务行为** | 任何「规范化」都不得改变计算结果、金额口径、并发语义、接口契约 |
| 2 | **不破坏数据与环境** | 不删用户文件、不误杀进程、不把系统留在脏状态 |
| 3 | **门禁必须通过** | `./scripts/verify.sh` exit 0 |
| 4 | 遵守规范文档 | 本目录全部 `.md` |
| 5 | 代码更"好看" | **最低优先级**。风格问题不得以破坏 1~4 为代价 |

**遇到「规范要求 vs 现状不一致」时**：不要自行裁决。在改动说明里列出冲突点，
由人决定。典型例子：`common/Views.java` 违反「VO 独立文件」，但它被 4 个域共用，
拆散风险远大于收益 —— 这类已有明确豁免（见 §8）。

## 2. 强制性工作流（7 步，不得跳过）

```
① 读规范 → ② 查现状 → ③ 检查 Git → ④ 改代码
   → ⑤ 跑门禁 → ⑥ 启动验证（若涉及运行期）→ ⑦ 更新文档并自证
```

### ① 读规范

改什么域读什么文档：

| 要改的东西 | 必读 |
|---|---|
| 新增/移动 Java 文件 | `DIRECTORY_STRUCTURE.md` |
| 写 Java 代码 | `BACKEND_CODING_STANDARDS.md` |
| 写注释 | `COMMENT_STANDARDS.md` |
| 写 SQL / Mapper | `DATABASE_CODING_STANDARDS.md` |
| 改前端 | `FRONTEND_CODING_STANDARDS.md` |
| 改脚本 | `SCRIPT_CODING_STANDARDS.md` |
| 任何改动 | `CODE_STANDARDS.md` + 本文档 |

### ② 查现状（禁止假设）

**禁止**在没读代码的情况下说"应该没问题"。至少确认：

| 要确认的事 | 怎么做 |
|---|---|
| 目标类/方法当前长什么样 | 读文件，不要靠记忆 |
| 有没有现成的 Service 可复用 | `grep -rn "class XxxService"` |
| 依赖的接口签名 | 读接口文件 |
| 数据库列的真实约束 | 查 `information_schema`，不要看迁移文件猜 |
| 现有命名惯例 | `grep` 同后缀的类看命名模式 |

### ③ 检查 Git 工作区

```bash
git status --porcelain     # 有未提交改动 → 先问人，不要覆盖
git log --oneline -5       # 确认基线
```

**禁止**：覆盖他人未提交的改动；未经授权 `commit` / `push` / `reset --hard` / `checkout --`。

### ④ 改代码

按 §3~§7 的规则。改动**只做一件事**，不夹带格式化与无关重命名。

### ⑤ 跑门禁

```bash
./scripts/verify.sh          # 必须 exit 0
```

失败时按 `QUALITY_GATE.md` §5 排查。**不得通过修改检查脚本来让它通过**（见 §4 R-20）。

### ⑥ 启动验证（涉及运行期时必须做）

触发条件（任一即需）：

- 改了 Controller / Service / Mapper / 事务 / 配置类
- 移动或重命名了包
- 改了 `application.yml` / 迁移脚本 / Lua 脚本
- 改了 `@MapperScan` / 组件扫描范围

```bash
./scripts/verify.sh --fast            # 先确保编译过
./start.command backend               # 或 java -Dserver.port=8097 -jar target/*.jar
curl -s http://127.0.0.1:8097/api/... | head -c 400   # 调一次真实接口
```

判定标准：返回 `code=0`，且关键字段符合预期（不能只看 HTTP 200）。

> **「编译通过 ≠ 装配成功」**：Mapper 绑定、`@Transactional` 代理、
> Bean 循环依赖、`@Value` 占位符缺失都只在运行期暴露。

### ⑦ 更新文档并自证

| 改了什么 | 必须同步 |
|---|---|
| 新增/移动目录或包 | `DIRECTORY_STRUCTURE.md` §2 |
| 新增/删除接口 | `docs/api/AI_COST_API.md` |
| 新增/修改表 | `docs/database/TABLE_DICTIONARY.md` |
| 新增脚本或门禁项 | `QUALITY_GATE.md` / `SCRIPT_CODING_STANDARDS.md` |
| 修复了审计登记的问题 | `PROJECT_CODE_AUDIT.md` §7（附验证证据） |
| 改了技术栈版本 | `CODE_STANDARDS.md` 锁版表 |

**自证格式**（在交付说明里写清，不接受"已完成"三个字）：

```
本批目标：
实际修改文件：（逐个列出）
修改原因：
规范应用情况：（对照哪条规范）
测试命令：
真实测试结果：（贴实际输出，不是"应该能过"）
启动验证：（接口 + 返回摘要，若涉及运行期）
遗留问题：
下一批任务：
```

## 3. 必须遵守的 22 条规则

### A. 改动边界（1~5）

| # | 规则 |
|---|---|
| **A1** | **不改变业务行为**。重构只动结构，不动计算结果、金额口径、并发语义、接口契约。若必须改行为，单独列出并声明。 |
| **A2** | **不随意升级技术栈**。版本变更必须单独评审，并同步 `CODE_STANDARDS.md` 锁版表。 |
| **A3** | **不为达到目录规范而做无意义的大规模迁移**。移动包必须有明确的边界收益，且按 §5 流程执行。 |
| **A4** | **一次改动只做一件事**。不夹带格式化、重命名、无关修复。 |
| **A5** | **不覆盖他人未提交的改动**。动手前 `git status --porcelain`，非空则先问。 |

### B. 代码与结构（6~11）

| # | 规则 |
|---|---|
| **B6** | 新增 Java 文件必须能走通 `DIRECTORY_STRUCTURE.md` §7 决策树；走不通就提规范缺口，**不要自己发明目录**。 |
| **B7** | **Controller 不得 import Mapper**，不得包含业务判断。所有数据访问经 Service。 |
| **B8** | 新增方法 **≤50 行**，参数 ≤7 个（超过用 `record` 聚合），嵌套 ≤3 层。 |
| **B9** | **只用构造器注入**，字段 `final`。禁止 `@Autowired` 字段注入。 |
| **B10** | **金额只用 `BigDecimal`**；对外传输用 `String`（`toPlainString()`）；`divide` 必须指定 scale 与 `RoundingMode`。 |
| **B11** | **时间只用注入的 `Clock`**：`LocalDateTime.now(clock)`。禁止裸 `LocalDate(Time).now()` / `new Date()`。 |

### C. 数据与 SQL（12~15）

| # | 规则 |
|---|---|
| **C12** | **禁止 `SELECT *`**，列清单必须显式且与实体字段对应。 |
| **C13** | **禁止 `${}` 插值**。唯一例外是 `ORDER BY`，且白名单必须下沉到 DTO `setter`（任何赋值路径都过滤）。 |
| **C14** | **迁移文件只增不改**。`V1~V5` 已执行，一个字符都不能动；新增从 `V6__` 起。种子数据写 `ON DUPLICATE KEY UPDATE`。 |
| **C15** | **表与每个字段必须有 `COMMENT`**，枚举字段列出全部取值；金额 `DECIMAL(20,8)`；时间 `DATETIME(3)` 且注明 UTC；**禁止物理外键**。 |

### D. 前端（16~18）

| # | 规则 |
|---|---|
| **D16** | **禁止视图/组件 `import axios`**，请求一律走 `api/request.ts`；**禁止写死后端 host**。 |
| **D17** | **禁止 `any` / `@ts-ignore`**。后端返回必须有显式 interface；**金额不得 `Number()` 后参与运算**。 |
| **D18** | 统一 `<script setup lang="ts">` + 类型化 props + `withDefaults`；样式引用 `var(--color-*)`，不写硬编码色值；`v-for` 必须有稳定 `:key`。 |

### E. 脚本与运维（19~21）

| # | 规则 |
|---|---|
| **E19** | **禁止 `kill -9` / `killall` / `pkill -f` / 按端口杀进程**。只能读自己写的 `.run/*.pid` 精确关停，只用 `SIGTERM`。 |
| **E20** | 脚本必须 `set -Eeuo pipefail`（探测型可只 `-uo pipefail` 并写明原因）；**变量后紧跟非 ASCII 必须写 `${VAR}`**（macOS bash 3.2）；改系统状态必须 `trap ... EXIT` 兜底。 |
| **E21** | **禁止 `rm -rf "$VAR"`**（必须 `${VAR:?}`）；禁止硬编码 `/Users/...`；禁止脚本内明文密钥。 |

### F. 交付（22）

| # | 规则 |
|---|---|
| **F22** | **交付必须自证**：贴真实命令输出（测试结果、接口返回、库内数据），不接受"应该可以""已完成"。**不为通过检查而修改检查本身。** |

## 4. 绝对禁止清单

> 这些行为会直接导致改动被回退，并视为严重违规。

| # | 禁止 | 原因 |
|---|---|---|
| **R-01** | 未获授权就 `git push` / 发布 / 部署 | 用户明确要求逐次确认 |
| **R-02** | 修改 `V1~V5` 已执行迁移文件 | 已上线环境 schema 与代码不一致 |
| **R-03** | 用 `git reset --hard` / `checkout --` 丢弃改动 | 会丢他人的工作 |
| **R-04** | 为了让门禁通过而放宽/删除检查规则 | 门禁失去意义，比没有更糟 |
| **R-05** | 改测试断言去迁就有问题的代码 | 掩盖缺陷 |
| **R-06** | 写 `TODO` / 空实现 / `throw new UnsupportedOperationException` 冒充功能 | 违反执行纪律 |
| **R-07** | 提交 `target/` `node_modules/` `dist/` `.run/` | 仓库污染 |
| **R-08** | 提交含真实密钥的文件（`.env`） | 密钥泄漏，且进 git 历史无法清除 |
| **R-09** | 删除或改写 `docs/engineering/` 下的规范以"简化" | 规范是契约 |
| **R-10** | 声称"已完成"但没跑过验证 | 见 F22 |
| **R-11** | 在日志里打印 API Key / 完整 Prompt / 用户 PII | 机密泄漏 |
| **R-12** | 用 `kill -9` / `pkill -f` / `taskkill /IM` 关进程 | 误杀其他项目 |
| **R-13** | 把系统留在脏状态退出（改了额度/开关不恢复） | 后续所有请求受影响，且无从察觉 |
| **R-14** | 在没读代码的情况下断言"这里没问题" | 本项目的 `SELECT *` 曾被误判为 0 处 |
| **R-15** | 为「统一风格」大规模重排已有代码 | 淹没真正的改动 |

## 5. 高风险操作流程

### 5.1 移动/重命名包

```
1. git status --porcelain 必须为空
2. 用 git mv（不是 mv），保留历史
3. 批量改 package/import：按真实源根分别计算 src/main/java 与 src/test/java
4. mvn test-compile
5. mvn -Pintegration verify
6. 启动服务 + 调至少 1 个真实接口（Mapper 绑定只在运行期暴露）
7. find src -type d -empty -delete
8. 同步 DIRECTORY_STRUCTURE.md §2 + PROJECT_CODE_AUDIT.md
```

> **血泪教训**：迁移脚本对 `src/test/java` 套用了 `src/main/java` 的相对路径算法，
> 结果 test 文件包声明被写成 `package ......test.java.com.example.ai.token.cost;`，
> 13 个文件全部编译失败。
> 另一个教训：包拆分后原本同包的类互相找不到，编译期才报"找不到符号"。

### 5.2 改数据库

```
1. 先查真实约束：information_schema.COLUMNS（不要看迁移文件猜）
2. 新增 V6__*.sql；已执行文件不动
3. 评估 NOT NULL：必须给 DEFAULT 或允许 NULL
4. 应用层配合：INSERT 显式传参时 null 不会被数据库默认值兜住
5. 跑集成测试（会连真实库）
6. 用 SQL 核对结果，不要只看接口返回
```

### 5.3 改脚本

```
1. 改完立即 bash -n
2. 跑 ./scripts/check-scripts.sh（33 项）
3. 实测三条路径：正常运行 / 未运行时（幂等）/ 进程已死（脏 PID 文件）
4. 双击兼容性：.command 有 +x，.bat 有 chcp 65001
```

## 6. 本项目的 9 个真实陷阱（每条都踩过）

> 这些不是理论风险。每条都造成过实际的错误结论或线上缺陷。

| # | 陷阱 | 现象 | 正确做法 |
|---|---|---|---|
| 1 | **JDK 23+ 关闭隐式注解处理** | Lombok 静默失效，数百处"找不到符号 getXxx()"，报错完全指不到根因 | `JAVA_HOME` 必须锁定 17~22；`scripts/check-backend.sh` 已在入口拦截 |
| 2 | **BSD grep 不支持 BRE 的 `\|`** | `grep "a\|b"` **静默 0 命中** → 把 31 处 `SELECT *` 误判为 0 处 | **一律 `grep -E`** |
| 3 | **BSD grep 不支持 `\b`** | `grep -E '\bpkill\b'` 静默 0 命中 | `[[:<:]]pkill[[:>:]]` 或 `(^\|[^A-Za-z0-9_])pkill` |
| 4 | **BSD grep 不支持 `-P`** | `grep: invalid option -- P` | 用 `perl -ne` |
| 5 | **macOS bash 3.2 多字节变量界定** | `echo "$VAR（中文"` → `VAR\\xef: unbound variable`，报错行号指不到真正原因 | 变量后跟非 ASCII **必须 `${VAR}`** |
| 6 | **`Set.of(...).contains(null)` 抛 NPE** | 不是返回 false，而是抛异常 | 显式判 `null`（`UsageQuery.setSort` 已修） |
| 7 | **`Map.of(...)` 不接受 null 键** | `getOrDefault(null, v)` 抛 NPE | 同上 |
| 8 | **`mvn ... \| tail` 吞退出码** | 命令失败但退出码是 tail 的 0，误以为成功 | 重定向到文件，单独取退出码 |
| 9 | **INSERT 显式传参使数据库默认值失效** | 列是 `NOT NULL DEFAULT 'BLOCK'`，Java 传 null → 500 | Java 侧补全所有 NOT NULL 列默认值 |

**使用建议**：任何"我确认这里没有问题"的结论，先用第 2~4 条检验你的检查命令是否真的有效
（造一个必然命中的样本验证）。做不到就不许写"0"。

## 7. 提交前自查（10 问）

逐条回答"是"才能提交：

1. `./scripts/verify.sh` 真的跑过，且 exit 0？
2. 涉及运行期的改动，真的启动并调过接口？
3. 改动只做了一件事？
4. 没有改测试去迁就代码？
5. 没有新增 `TODO` / 空实现 / 注释掉的代码？
6. 相关文档已同步（目录/接口/表/门禁）？
7. 交付说明里有**真实输出**，不是"应该可以"？
8. 没有覆盖他人的未提交改动？
9. 没有未经授权 commit / push？
10. 如果我的某个检查结论是"0 处/无问题"，我验证过检查命令本身有效吗？

## 8. 明确豁免清单（不要"修正"它们）

以下内容**已经过评估并决定保持现状**。智能体不得以"符合规范"为由改动：

| # | 豁免项 | 理由 |
|---|---|---|
| 1 | `com.example.milvusdemo.**`（6 个文件） | Milvus + Spring AI 教学示例，与成本治理主业务无耦合。**冻结**：不重构、不迁移、不补注释、允许保留 `Map` 返回。仅允许「不改就无法编译」的适配性修改。 |
| 2 | 18 个 Service 不建接口 / `service/impl` | 无 ≥2 实现、无 SPI、无 AOP 增强需求。空接口只增加跳转成本。`provider/adapter/` 是「有 2 个实现才建接口」的正确示例。 |
| 3 | `common/Views.java` 内联 12 个 record | 4 个域共用的统计契约，拆散会波及全部 Controller 与前端类型。**冻结扩容**：可改字段，禁止新增 record，禁止新增对业务域的 import。 |
| 4 | `V1~V5` 迁移文件 | 已执行，改动会导致 Flyway 校验和不匹配。 |
| 5 | 前端 10 个视图的硬编码色值 | 一次性替换属大规模样式迁移，风险大于收益。Stylelint 已设为 **warning** 收集清单，分批收敛后再升 error。 |
| 6 | 前端不建 `modules/` 目录 | 规模未到阈值（10 视图 / 13 组件）。 |
| 7 | `DemoApplication` 位于 `milvusdemo` 包 | 移动会改变 Spring Boot 默认扫描根，高风险低收益。 |
| 8 | `@Slf4j` 未使用（12 个类手工 `LoggerFactory`） | 混用两种风格更糟。若迁移应一次性全改并登记 ADR。 |

**新增豁免必须**：在本节登记 + 在 `CODE_STANDARDS.md` §4 说明理由 + 经人确认。
